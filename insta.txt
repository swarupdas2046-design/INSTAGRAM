4. Backend startup flow
-----------------------

Step by step request start hone se pehle project ka flow:

1. `Backend/server.js` run hota hai.
2. `dotenv/config` environment variables load karta hai.
3. `app` import hota hai from `src/app.js`.
4. `Database()` call hota hai from `src/config/database.js`.
5. `Database()` `process.env.MONGO_URL` se MongoDB connect karta hai.
6. Server `PORT` env se port leta hai, nahi mila to `5000` use karta hai.
7. `app.listen(port)` backend ko live kar deta hai.

Required `.env` values:

PORT=5000
MONGO_URL=your_mongodb_connection_string
JWT_SECRET_KEY=your_jwt_secret
IMAGEKIT_URL_ENDPOINTS=your_imagekit_url_endpoint
IMAGEKIT_PUBLIC_SECRET=your_imagekit_public_key
IMAGEKIT_PRIVATE_SECRET=your_imagekit_private_key


5. app.js ka role
-----------------

File: `Backend/src/app.js`

Yeh main Express app configure karta hai.

Middlewares:

1. `express.json()` - JSON body parse karta hai.
2. `cookie-parser` - cookies read karta hai. Auth middleware `req.cookies.jwt_token` isi se read karta hai.
3. `express.urlencoded({ extended: true })` - form/urlencoded data parse karta hai.

Routes:

1. `/api/auth` - auth routes yahan mount hain.
2. `/api/post` - post routes yahan mount hain.

Last middleware:

1. `errorMiddleware` - route/controller/service errors ko final JSON error response banata hai.


6. Common utility pattern
-------------------------

Project me controllers ko clean rakhne ke liye utils banaye gaye hain.

6.1 `ApiResponse`

File: `Backend/src/utils/apiResponse.js`

Successful response ka common format:

{
  success: true,
  message: "...",
  data: ...
}

6.2 `ApiError`

File: `Backend/src/utils/apiError.js`

Custom error throw karne ke liye:

throw new ApiError("Unauthorized", 401)

Isme `message` and `statusCode` store hota hai.

6.3 `asyncHandler`

File: `Backend/src/utils/asyncHandler.js`

Express async controllers me try/catch baar-baar likhne se bachata hai.

Flow:

1. Controller function ko wrap karta hai.
2. Agar promise reject hota hai ya error throw hota hai to `.catch(next)` call karta hai.
3. Error automatically `errorMiddleware` tak pahunch jata hai.

6.4 `token.js`

File: `Backend/src/utils/token.js`

Functions:

1. `generateToken(userId)`
   - JWT create karta hai.
   - Payload: `{ id: userId }`
   - Secret: `process.env.JWT_SECRET_KEY`
   - Expiry: `1D`

2. `Verify_Token(Token)`
   - JWT verify karta hai.
   - Valid token hai to decoded payload return karta hai.


7. Error handling flow
----------------------

File: `Backend/src/middlewares/error.middleware.js`

Error flow:

1. Controller/service/middleware me `throw new ApiError(...)`.
2. Controller `asyncHandler` se wrapped hai.
3. `asyncHandler` error ko `next(err)` se Express ko deta hai.
4. `app.js` ke end me `errorMiddleware` run hota hai.
5. Response format:

{
  success: false,
  message: "Error message"
}

Default:

1. Status code nahi mila to `500`.
2. Message nahi mila to `"Internal Server Error"`.


8. User model
-------------

File: `Backend/src/models/user.model.js`

Mongoose model name: `UserInfo`

Fields:

1. `username` - String, required, unique, trim
2. `email` - String, required, unique, trim
3. `password` - String, required, trim, minLength 6
4. `bio` - optional String
5. `profileImage` - String with default user image URL
6. timestamps - `createdAt`, `updatedAt`

Important model logic:

1. `userSchema.pre("save", function () {...})`
   - User save hone se pehle password hash karta hai.
   - Agar password modified nahi hai to hashing skip hoti hai.
   - bcrypt sync hashing use ho raha hai: `bcrypt.hashSync(password, 10)`.

2. `userSchema.methods.comparePassword`
   - Login time plain password ko hashed password se compare karta hai.
   - `bcrypt.compareSync(password, this.password)` use hota hai.


9. Authentication feature
-------------------------

Auth ka code 3 layers me divided hai:

1. Route
2. Controller
3. Service

Current pattern:

Route decides endpoint -> Controller handles req/res -> Service handles business logic/database -> Controller sends response.


9.1 Auth routes

File: `Backend/src/routes/auth.route.js`

Base path in app.js: `/api/auth`

Routes:

1. `POST /api/auth/register`
   - Controller: `UserRegister`
   - Access: Public

2. `POST /api/auth/login`
   - Controller: `UserLogin`
   - Access: Public


9.2 Register step by step

Endpoint: `POST /api/auth/register`

Request body:

{
  "email": "test@example.com",
  "password": "123456",
  "username": "testuser",
  "bio": "optional bio",
  "profileImage": "optional image url"
}

Flow:

1. Request `/api/auth/register` par aati hai.
2. `auth.route.js` request ko `UserRegister` controller me bhejta hai.
3. `UserRegister` controller `registerService(req.body)` call karta hai.
4. `registerService` body se `email`, `password`, `username`, `bio`, `profileImage` leta hai.
5. Validation:
   - email missing hai to error
   - password missing hai to error
   - username missing hai to error
   - password length 6 se kam hai to error
   - username length 3 se kam hai to error
6. Existing user check:
   - `userModel.findOne({ $or: [{ email }, { username }] })`
   - Same email ya username already hai to `409` error.
7. New user create:
   - `userModel.create({ email, password, username, bio, profileImage })`
8. User save hone se pehle user model ka pre-save hook password hash karta hai.
9. User create hone ke baad `generateToken(NewUser._id)` JWT banata hai.
10. Service controller ko `{ NewUser, JWT_Token }` return karta hai.
11. Controller cookie set karta hai:
   - Cookie name: `jwt_token`
   - Cookie value: JWT
   - `httpOnly: true`
12. Controller user ka safe data response me bhejta hai.
13. Password response me nahi bheja jata.

Success response:

{
  "success": true,
  "message": "User Register Successfully",
  "data": {
    "_id": "...",
    "email": "...",
    "username": "...",
    "bio": "...",
    "profileImage": "...",
    "createdAt": "...",
    "updatedAt": "..."
  }
}


9.3 Login step by step

Endpoint: `POST /api/auth/login`

Request body with email:

{
  "email": "test@example.com",
  "password": "123456"
}

Request body with username:

{
  "username": "testuser",
  "password": "123456"
}

Flow:

1. Request `/api/auth/login` par aati hai.
2. `auth.route.js` request ko `UserLogin` controller me bhejta hai.
3. `UserLogin` controller `loginService(req.body)` call karta hai.
4. `loginService` body se `email`, `username`, `password` leta hai.
5. Validation:
   - password missing hai to `400`
   - password length 6 se kam hai to `400`
6. User find hota hai:
   - username ya email dono me se kisi ek se login possible hai.
   - Query: `$or: [{ username }, { email }]`
7. User nahi mila to `404 User not found`.
8. Password compare:
   - `isExistedUser.comparePassword(password)`
   - Yeh model method bcrypt compare karta hai.
9. Password galat hai to `401 Invalid Password`.
10. Password sahi hai to JWT generate hota hai.
11. Controller cookie set karta hai:
   - Cookie name: `jwt_token`
   - `httpOnly: true`
12. Safe user data response me return hota hai.


9.4 Auth middleware

File: `Backend/src/middlewares/auth.middleware.js`

Purpose: protected routes par sirf logged-in user ko access dena.

Flow:

1. Cookie se token read hota hai: `req.cookies.jwt_token`
2. Token missing hai to `401 Unauthorized`
3. Token verify hota hai: `Verify_Token(token)`
4. Token invalid/expired hai to `401 User not authorized`
5. Decoded token se user id milti hai: `decode.id`
6. DB me user find hota hai: `userModel.findById(decode.id)`
7. User nahi mila to `401 Unauthorized`
8. User mil gaya to `req.user = User`
9. `next()` call hota hai, then actual protected controller run hota hai.

Important:

Post routes me controller directly `req.user` use karta hai, so auth middleware pehle run hona zaroori hai.

13. Create post step by step
----------------------------

Endpoint: `POST /api/post/`

Access: authenticated user only.

Request type: `multipart/form-data`

Fields:

1. `imageUrl` - file field name must be exactly `imageUrl`.
2. `caption` - optional text field.

Flow:

1. Client request send karta hai with cookie `jwt_token`.
2. Route par sabse pehle `authMiddleware` run hota hai.
3. Auth middleware token verify karke `req.user` set karta hai.
4. Next `Upload.single("imageUrl")` run hota hai.
5. Multer image ko disk par save nahi karta; memory me buffer banata hai.
6. Controller `PostController` run hota hai.
7. Controller data leta hai:
   - `const User = req.user`
   - `const file = req.file`
   - `const { caption } = req.body`
8. File missing hai to `400 Image is required`
9. File present hai to ImageKit upload:
   - `sendFile(file.buffer, file.originalname, "posts")`
10. ImageKit upload fail hua to `500 Image Upload Failed`
11. Upload success hua to MongoDB me post create:
   - `user: User._id`
   - `caption`
   - `imageUrl: { url: data.url, fieldId: data.fileId }`
12. Response message: `Post Created SuccessFully`


14. Get all posts step by step
------------------------------

Endpoint: `GET /api/post/all-posts`

Access: authenticated user only.

Flow:

1. Client cookie ke sath request bhejta hai.
2. `authMiddleware` token verify karta hai.
3. `req.user` me logged-in user set hota hai.
4. `getAllPost` controller run hota hai.
5. Controller query chalata hai: `postModel.find({ user: user._id })`
6. Current behavior:
   - Yeh sirf logged-in user ke posts fetch karta hai.
   - Global feed nahi hai.
7. Response message: `Posts Fetched Successfully`

Important note:

`find()` empty array return karta hai agar posts nahi mile. Empty array truthy hota hai, so `if (!allPosts)` normally trigger nahi hoga. Agar "no posts" handle karna ho future me, `allPosts.length === 0` check kar sakte ho.


15. Get single post detail step by step
---------------------------------------

Endpoint: `GET /api/post/detail/:id`

Example: `GET /api/post/detail/65abc...`

Access: authenticated user only.

Flow:

1. Client cookie ke sath request bhejta hai.
2. `authMiddleware` token verify karta hai.
3. `req.user` set hota hai.
4. Controller `postDetails` run hota hai.
5. URL params se post id leta hai: `req.params.id`
6. Post id missing hai to `404 post not found`
7. DB me post find hota hai: `postModel.findById(postId)`
8. Post nahi mila to `404 Post not found`
9. Ownership check hota hai: `data.user.equals(req.user._id)`
10. Agar logged-in user post owner nahi hai to `403 forbidden access`
11. Owner valid hai to post data return hota hai.

Why ownership check?

Abhi single post detail route private hai. User sirf apna post detail dekh sakta hai. Instagram style public post detail banana ho to ownership check ko change karna padega.


16. Follow model / edge collection
----------------------------------

File: `Backend/src/models/follow.model.js`

Purpose: followers/following relation ko separate collection me store karna.

Why separate collection?

Instagram type app me kisi user ke millions followers ho sakte hain. Agar followers array user document ke andar rakhenge to:

1. MongoDB document bahut bada ho sakta hai.
2. 16MB document limit issue aa sakta hai.
3. Popular user ko follow/unfollow karte time same document baar-baar update hoga.
4. Scaling hard hogi.

Better approach:

Users are nodes. Follow documents are edges.

Example:

User A follows User B:

{
  "follower": "UserAId",
  "followed": "UserBId"
}

Current schema:

1. `follower` - ref to `UserInfo`, who is following
2. `followed` - ref to `UserInfo`, whom they follow
3. timestamps

Important note:

Current schema shape is:

follower: {
  user: mongoose.Schema.Types.ObjectId,
  ref: "UserInfo",
  required: [...]
}

For Mongoose refs, a cleaner future shape would be:

follower: {
  type: mongoose.Schema.Types.ObjectId,
  ref: "UserInfo",
  required: true
}

followed: {
  type: mongoose.Schema.Types.ObjectId,
  ref: "UserInfo",
  required: true
}

Also add unique index later:

followSchema.index({ follower: 1, followed: 1 }, { unique: true })

This prevents same user following same target multiple times.

21. Mental model of the project
-------------------------------

Request ka general flow:

Client request
  -> app.js middleware
  -> route file
  -> auth middleware if protected
  -> controller
  -> service if business logic is separated
  -> model/database
  -> ApiResponse success

Error flow:

Any error
  -> ApiError throw
  -> asyncHandler catch
  -> errorMiddleware
  -> JSON error response

Auth flow:

Register/login
  -> user validate
  -> password hash/compare
  -> JWT generate
  -> cookie set
  -> protected routes can use cookie token

Post flow:

Logged-in user
  -> authMiddleware sets req.user
  -> multer reads image file
  -> ImageKit uploads file
  -> MongoDB stores post data
  -> response returns created/fetched post
